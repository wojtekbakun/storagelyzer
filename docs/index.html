Sizes you can trustRozmiary, którym można ufać

“On disk” counts the blocks a file really takes, like du. “Size” is the length Finder shows. When the two differ wildly, say a 1 TB Docker disk image that takes 20 GB, the app lists the files behind the gap: sparse files, files kept only in iCloud and compressed files.

„Na dysku” liczy bloki, które plik naprawdę zajmuje, jak du. „Rozmiar” to długość, którą pokazuje Finder. Gdy te liczby bardzo się różnią, np. obraz dysku Dockera ma 1 TB, a zajmuje 20 GB, aplikacja wymienia pliki, które za tym stoją: rzadkie, trzymane tylko w iCloud i skompresowane.

  • Hard links count onceTwarde dowiązania liczone raz
  • Switching morphs the chartPrzełączenie przekształca wykres

Free up space, safelyBezpieczne zwalnianie miejsca

The clean-up assistant measures what hides behind macOS “System Data”: app caches, logs, Xcode and simulator data, developer tool caches, old iPhone backups, installers and Time Machine snapshots. It also ranks your apps by size with when you last opened them, and finds data left behind by apps you have uninstalled.

Asystent sprzątania mierzy, co kryje się za „Danymi systemowymi” w macOS: pamięć podręczną aplikacji, logi, dane Xcode i symulatorów, cache narzędzi deweloperskich, stare kopie iPhone'a, instalatory i lokalne migawki Time Machine. Pokazuje też aplikacje według rozmiaru z datą ostatniego otwarcia i znajduje dane, które zostały po odinstalowanych programach.

  • Everything goes to the Trash firstWszystko najpierw trafia do Kosza
  • No hard-coded app listBez listy aplikacji na sztywno

One folder, two waysJeden folder, dwa sposoby

macOS's own Storage settings sum the disk up in categories, and whatever the system can't place lands in System Data, which you can't manage directly. To find out which folders take the space, the usual tool is du in the Terminal. Here is the same folder both ways, on the author's Mac.

Ustawienia „Pamięć masowa” w macOS podsumowują dysk w kategoriach, a to, czego system nie przypisze, trafia do „Danych systemowych”, którymi nie da się zarządzać bezpośrednio. Żeby sprawdzić, które foldery zajmują miejsce, zwykle sięga się po du w Terminalu. Oto ten sam folder na dwa sposoby, na Macu autora.

Both sides are real output for /System/Library on the same Mac, one run each; the table below has medians of seven. Both report the same total, 29,574,684,672 bytes. du -h counts in binary units (1G is 1024³ bytes), which is why its 17G for AssetsV2 is the 17.8 GB on the right. For the demo, the scan is kept to its 19,924 biggest items, and everything smaller is drawn in the grey slices.

Obie strony to prawdziwy wynik dla /System/Library na tym samym Macu, po jednym uruchomieniu; tabela niżej podaje mediany z siedmiu. Oba narzędzia podają tę samą sumę: 29 574 684 672 bajtów. du -h liczy w jednostkach binarnych (1G to 1024³ bajtów), dlatego jego 17G dla AssetsV2 to 17,8 GB po prawej. W demo skan jest ograniczony do 19 924 największych elementów, a wszystko mniejsze trafia do szarych wycinków.

Under the hoodPod maską

A scanner tuned for APFSSkaner dostrojony do APFS

A disk analyzer is only as good as its scanner. Storagelyzer's is written in Rust around how APFS actually behaves, and the interface is React and TypeScript, drawn on a canvas in the system WebView.

Analizator dysku jest tak dobry, jak jego skaner. Ten w Storagelyzerze jest napisany w Ruście pod to, jak naprawdę zachowuje się APFS, a interfejs to React i TypeScript, rysowany na canvasie w systemowym WebView.

  • getattrlistbulk(2)

    Many files per system callWiele plików na jedno wywołanie

    Instead of readdir plus lstat for every file, one call returns names, types, sizes, inodes and mount status for a whole batch of entries.

    Zamiast readdir i lstat dla każdego pliku jedno wywołanie zwraca nazwy, typy, rozmiary, i-węzły i status montowania dla całej paczki wpisów.

  • STORAGELYZER_THREADS=4

    Four threads is the sweet spotCztery wątki to optimum

    APFS does not list directories faster with more threads: sixteen were 2–5× slower than four, even with no locking in the app. Four is the default.

    APFS nie listuje katalogów szybciej przy większej liczbie wątków: szesnaście było 2–5× wolniejsze niż cztery, nawet bez żadnych blokad w aplikacji. Domyślnie są cztery.

  • /usr/share/firmlinks

    Nothing counted twiceNic nie liczy się podwójnie

    Since Catalina, /Users and /Applications are firmlinks into the Data volume. Directories are deduplicated by device and inode, volumes from the same container are scanned in a second pass, and hard links count once.

    Od Cataliny /Users i /Applications to firmlinki do woluminu Data. Katalogi są deduplikowane po urządzeniu i i-węźle, woluminy z tego samego kontenera skanowane w drugim przebiegu, a twarde dowiązania liczone raz.

  • IOPOL_TYPE_VFS_MATERIALIZE_DATALESS_FILES

    Never downloads from iCloudNic nie ściąga z iCloud

    Scanner threads turn off file materialization, so cloud-only files count at their local size and nothing is fetched. Access times stay untouched, and other disks and network shares are skipped.

    Wątki skanera mają wyłączone pobieranie plików, więc pliki tylko w chmurze liczą się z lokalnym rozmiarem i nic nie jest ściągane. Czasy dostępu zostają nietknięte, a inne dyski i udziały sieciowe są pomijane.

  • ≈ 48 B / node

    The file tree stays in RustDrzewo plików zostaje w Ruście

    Nodes live in a compact arena, about 48 bytes each plus the name, so two million files take about 140 MB. The interface gets only what it shows: a pruned subtree for the chart and pages of rows for the list.

    Węzły siedzą w zwartej arenie, ok. 48 bajtów na każdy plus nazwa, więc dwa miliony plików to ok. 140 MB. Interfejs dostaje tylko to, co pokazuje: przycięte poddrzewo do wykresu i strony wierszy dla listy.

  • buildMorph()

    Updates that morphAktualizacje, które się przekształcają

    Every progress update blends into the next: segments matched by id grow and slide, new ones emerge inside their parent, and removed ones shrink and fade. The hover labels glide along.

    Każda aktualizacja postępu płynnie przechodzi w następną: segmenty dopasowane po id rosną i przesuwają się, nowe wyłaniają się w obrębie rodzica, a znikające zwijają się i gasną. Etykiety płyną razem z nimi.

BuildInstalacja

Build it yourselfZbuduj u siebie

There is no signed download yet, so the app is built from source. You need macOS 11 or later, Rust, Node.js 20+ and the Xcode Command Line Tools.

Nie ma jeszcze podpisanej wersji do pobrania, więc aplikację buduje się ze źródeł. Potrzebujesz macOS 11 lub nowszego, Rusta, Node.js 20+ i Xcode Command Line Tools.

Terminal
git clone https://github.com/wojtekbakun/storagelyzer.git
cd storagelyzer
npm install
npm run install-app

The last command builds Storagelyzer.app and moves it to /Applications. Then give it Full Disk Access in System Settings → Privacy & Security → Full Disk Access. Without it, macOS hides Mail, Messages, Safari and other apps' data, so totals come out too low; the app tells you when that happens.

Ostatnie polecenie buduje Storagelyzer.app i przenosi go do /Applications. Potem nadaj mu Pełny dostęp do dysku w Ustawieniach systemowych → Prywatność i ochrona → Pełny dostęp do dysku. Bez tego macOS ukrywa dane Poczty, Wiadomości, Safari i innych aplikacji, więc sumy wychodzą za niskie; aplikacja daje znać, gdy tak się dzieje.

NoteBuilds are ad-hoc signed, so macOS ties Full Disk Access to one exact build. After installing a new one, switch the permission off and on again.

UwagaKompilacje są podpisane ad-hoc, więc macOS wiąże Pełny dostęp do dysku z jedną konkretną kompilacją. Po zainstalowaniu nowej wyłącz i włącz uprawnienie ponownie.
